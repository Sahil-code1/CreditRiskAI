# P_137 FastAPI + PostgreSQL Backend

This backend replaces the prototype/mock data path with:
- the real `loan_train.csv` source dataset (27,003 records)
- PostgreSQL storage
- the trained P_137 XGBoost model
- SHAP TreeExplainer responses
- real dashboard/analytics queries
- model evaluation metadata from the held-out 20% split

## 1. Start PostgreSQL

From the project root:

```bash
docker compose up -d postgres
```

## 2. Install backend dependencies

```bash
cd backend
python -m venv .venv
# Windows
.venv\Scripts\activate
pip install -r requirements.txt
```

## 3. Start API

From the project root:

```bash
python backend/run.py
```

On first startup, the backend creates tables and seeds the PostgreSQL database from `backend/data/loan_train.csv`. The model scores are generated by the actual P_137 XGBoost model.

API: http://localhost:8000
Docs: http://localhost:8000/docs

## 4. Start frontend

From the project root:

```bash
npm install
npm run dev
```

Frontend: http://localhost:5173

The frontend `.env` is already configured with:

```env
VITE_API_BASE_URL=http://localhost:8000
VITE_USE_MOCK=false
```

## Production notes

This project currently uses the real Kaggle-derived training dataset for portfolio analytics and the trained P_137 model for scoring. For a public deployment, move secrets to a secret manager, use a managed PostgreSQL database, HTTPS, proper user management, and a secured password-reset flow. Do not expose the local bootstrap credentials.
